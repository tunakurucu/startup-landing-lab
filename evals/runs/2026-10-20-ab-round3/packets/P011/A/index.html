Find the env var set on your laptop and nowhere else.

envcensus is a command-line checker for environment variables. It scans your codebase for every variable it reads, compares that list with .env.example and your CI config, and exits non-zero when one is missing or unused.

$npx envcensus
Read the help output

Runs on your machine and sends nothing anywhere. It reads your source files, .env.example and your CI config. Installing from npm is free; there is no account and no key.

Three files, one list, three kinds of problem

envcensus reads your source files for environment variable lookups and builds one list. It reads .env.example and your CI config the same way. Then it compares the three lists, name by name.

A variable passes when the code reads it, .env.example lists it, and CI sets it. Anything else is one of the three problems on the right, and each has a plain fix.

It does not read your .env values to decide, so the result is the same on every machine.

FindingWhat envcensus sawThe fix
missing from .env.example The code reads FEATURE_FLAGS_URL; .env.example has no such line. A new teammate copies the example and the app breaks on first run. Add FEATURE_FLAGS_URL= to .env.example, with a sample value if one is safe to share.
not set in CI The code reads STRIPE_WEBHOOK_SECRET; no env: entry in the workflow sets it. The job runs with undefined, and the failure shows up far from the cause. Set it in the workflow, usually from the CI’s secret store.
unused LEGACY_SMTP_HOST is in .env.example but nothing under src/ reads it. Every new environment gets a value that does nothing. Delete the line, or list the name as ignored if a tool outside the repo needs it.

In CI, a missing or unused variable fails the job

Add one step. envcensus exits 1 when it finds a problem, and any CI system treats a non-zero exit as a failed step. The log names the variable, the file and the line, so the fix is a one-line change in the pull request that caused it.

This is the step for the team that owns CI: it turns “works on my machine” into a check that runs on every push, with no service to host and no agent to install.

  • 0Every variable the code reads is in .env.example and set in CI, and none is unused.
  • 1At least one problem was found. The step fails.
  • 2envcensus could not run: a path or file it was told to read does not exist.

The help output is the documentation

There is no docs site yet. Everything the tool accepts is in envcensus --help, reproduced here in its current shape. Flag names can change before 1.0; the shipped text wins.

  • Install. npm install -g envcensus, or run it once with npx envcensus. There is no Homebrew formula yet; npm is the only install path.
  • Where it runs. On your machine or in a CI step. It makes no network calls and keeps no account. The only things it opens are your source files, .env.example and the CI config you point it at.
  • Source. The repository is private until 1.0. Until then, the npm package and this help text are what there is to read.
  • Who it is for. Any repo whose code reads environment variables and has a .env.example. If your variables live only in a secrets manager and never in the repo, envcensus has nothing to compare and is not for you yet.

Run it on your repo. It takes one command.

Open a terminal in any project with a .env.example and run the scan. The report is the one above, with your variables in it.

$npx envcensus

Nothing leaves your machine. Installing from npm is free; there is no account and no key.
