envcensus
Run it CI Help output npm

Every environment variable your code reads, checked against .env.example and CI.

envcensus scans the repository in front of it, lists each variable with the line that reads it, and tells you which ones nobody set and which ones nothing reads anymore. It runs on your machine and sends nothing anywhere.

$ npx envcensus

Needs Node.js and npm. No account, no config file, no network.

Three ways an environment variable goes wrong

Each one is a mismatch between two lists that nobody keeps in sync by hand: the variables your code reads, the ones .env.example promises, and the ones CI actually sets. envcensus builds all three and diffs them.

  • SESSION_SECRETmissing from .env.example

    Someone added a variable last sprint and set it in their own shell. The next person to clone the repo copies the example file, starts the app, and gets a stack trace instead of a login page.

  • STRIPE_SECRET_KEYnot set in ci.yml

    Tests pass on a laptop and fail in the pipeline. Or they pass in the pipeline because the code falls back to a default, and the real failure waits for production.

  • LEGACY_CACHE_TTLunused

    The code that read it was deleted a year ago. The example file keeps growing, every new hire sets it anyway, and nobody is sure what is safe to remove.

Run it on your own repo

The best way to judge it is to point it at code you know. It takes one command and prints a table like the one above. Nothing is written to disk and nothing is uploaded.

npm is the only install channel for now. There is no Homebrew formula yet.

once, without installing

$ cd your-repo
$ npx envcensus

or keep it around

$ npm install -g envcensus
$ envcensus # scans the current directory
$ envcensus services/api --example services/api/.env.sample

what counts as a read

process.env.STRIPE_SECRET_KEY
process.env["STRIPE_SECRET_KEY"]
const { PORT, LOG_LEVEL } = process.env
os.environ["DATABASE_URL"]   os.getenv("DATABASE_URL")
os.Getenv("REDIS_URL")
ENV["SESSION_SECRET"]        ENV.fetch("SESSION_SECRET")
$SMTP_HOST   ${SMTP_HOST}   # in shell scripts and Dockerfiles

Fail the build when something is missing

If you own the pipeline rather than the application: it is one step, needs no token, and makes no outbound request. "Set in CI" means the variable appears in the workflow file's env block or secrets mapping, so the check reads only what is already in the repo.

Opt a variable out with --allow-unused if the example file is deliberately broader than the code, or --ignore for generated directories.

.github/workflows/ci.yml

jobs:
  test:
    runs-on: ubuntu-latest
    env:
      DATABASE_URL: ${{ secrets.DATABASE_URL }}
      STRIPE_SECRET_KEY: ${{ secrets.STRIPE_SECRET_KEY }}
    steps:
      - uses: actions/checkout@v4
      - run: npx envcensus --format github
      - run: npm test

what the job sees when it fails

::error file=src/mail.ts,line=16::SMTP_PASSWORD is read here but not in .env.example or ci.yml
::error file=src/auth/session.ts,line=5::SESSION_SECRET is read here but not in .env.example
::warning file=.env.example,line=23::LEGACY_CACHE_TTL is not read anywhere
Process completed with exit code 1.

Exit codes

0
every variable accounted for
1
at least one variable is missing, or unused without --allow-unused
2
could not scan: bad path, unreadable file, or no example file found

The help output is the documentation

There is no docs site yet. This is what envcensus --help prints, reproduced here so you can read it before you install anything. If a flag is not listed below, it does not exist.

envcensus --help

envcensus [directory] [options]

Find every environment variable the code in a directory reads
and check it against .env.example and CI workflow files.
Runs locally. Makes no network requests.

Options
  --example <file>      example file to check against
                        (default: .env.example)
  --ci <glob>           CI files to check, repeatable
                        (default: .github/workflows/*.yml)
  --ignore <glob>       paths to skip, repeatable
                        (node_modules, .git, dist and build
                        are always skipped)
  --allow-unused        do not fail on example variables
                        that nothing reads
  --format <kind>       table, json or github
                        (default: table)
  --no-color            plain output
  -h, --help            show this and exit
  -v, --version         print the version and exit

Exit codes
  0  every variable is read, in the example file and set in CI
  1  a variable is missing somewhere, or unused
  2  the scan could not run

Examples
  envcensus
  envcensus packages/api --example packages/api/.env.sample
  envcensus --ci ".gitlab-ci.yml" --format json > census.json
