Find the feature flags you should have deleted weeks ago.

flagsweep scans your code for feature flags, checks each one’s history in LaunchDarkly, Unleash or your config files, and lists the flags stuck on one value for weeks, with every file and line to change.

pipx install flagsweep

Open source, MIT licensed. Read the docs or see the code.

How to read it

  • Only flags past your cutoff
  • The value it’s stuck on, and how long
  • History from the flag service
  • What to do with the code
  • Every file and line that reads the flag

A flag is listed when its history goes flat.

flagsweep looks at what each flag has served over time. If it has served one value to everyone, with no change inside your cutoff, it’s listed. Flags mid-rollout or recently changed are left alone. Move the cutoff to see which of these flags would show up.

What happens when you run it

One command, run from the root of a repo.

  1. Scan the code

    flagsweep reads your source and finds every place a flag is evaluated, including tests.

  2. Check each flag’s history

    It looks up each flag in LaunchDarkly, Unleash or your config files to see what it has served and when that last changed.

  3. List what can go

    Flags fully on or off past the cutoff are printed with the branch to keep and the files and lines to edit.

What it replaces

Old flags pile up because finding them is a chore nobody is assigned to.

Flag cleanup day

On the calendar every quarter. Bumped every quarter for a release.

The flag spreadsheet

Two hundred rows, an owner column that’s mostly blank, last edited by someone who left.

A list built from the code and the flag service

Nobody maintains it. Run flagsweep whenever you have half an hour and remove whatever it lists.
