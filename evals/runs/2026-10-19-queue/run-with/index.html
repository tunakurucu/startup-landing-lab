This getting-started guide covers the illustrative model only. It is not a verified package integration or an API reference.

node demo.mjs recover
node demo.mjs success
node demo.mjs fail

The recovery scenario emits the same job ID through queued, running, retrying, running and completed. The failure scenario ends in failed after the second attempt. Counts are example policy choices, not throughput measurements.

What does enqueue mean here?

The model creates a queued event before any running event. Advancing the interface only reveals a precomputed event sequence. The command-line example prints that sequence, without scheduling real background work.

A trace is a start.
It is not a reliability guarantee.

This example has a bounded retry path and a visible terminal failure. It does not establish persistence, delivery guarantees, production retry timing or behavior after a worker crash.

Before adopting the package, verify its storage requirements, shutdown handling and duplicate-execution behavior in the actual documentation. Make side effects safe to repeat.
