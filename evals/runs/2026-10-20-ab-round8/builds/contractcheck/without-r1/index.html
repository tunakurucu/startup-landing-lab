Three ways a response drifts from the spec

Each one compiles, passes unit tests, and breaks somebody else’s client. Contractcheck fails the check for all three.

Missing field

A required field stops appearing

A refactor drops a property from a serializer. The spec still lists it as required.

spec: currency (required)
got: no currency
Changed type

A field comes back as a different type

A number turns into a string, an object into an array, a value into null.

spec: amount_due integer
got: "4190" string
Undocumented status

A new error code nobody wrote down

An endpoint starts returning a status code the spec never mentions, so clients have no handler for it.

spec: 201, 400, 404
got: 409

How it runs

  1. Install the GitHub App

    Add Contractcheck from github.com/apps/contractcheck and choose the repositories it runs on.

  2. Point it at your spec and your staging API

    Tell it where your OpenAPI file lives in the repository and the base URL of your staging environment. The docs walk through setup.

  3. Open a pull request

    Contractcheck calls the operations in your spec against staging and compares every response to its schema and its documented status codes.

  4. Read the check on the pull request

    Green when every response matches. Red when one doesn’t, with the endpoint, the field, what the spec expects and what staging sent.

Find out on the pull request, not from a bug report

Without a check, a broken contract usually reaches you through someone else.

Today

  1. A change to a response merges. Unit tests pass.
  2. It ships. A client team’s parser fails on "4190".
  3. They file a bug. You trace it back through a week of merges.
  4. The Postman collection that would have caught it hasn’t been run since spring.

With Contractcheck

  1. The change opens as a pull request.
  2. The check fails on that pull request, naming amount_due and the spec line.
  3. The author fixes the code or updates the spec before merging.
  4. The spec stays the source of truth, checked on every pull request, with nothing to maintain by hand.
