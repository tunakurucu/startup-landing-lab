Expected number. Got string.

Contractcheck is a GitHub App for backend teams. On every pull request it runs your OpenAPI spec against your staging API, and fails the check when a response stops matching the spec.

Install the GitHub App Read the docs

Free for public repositories; $19 a month per private repository. It reads responses from your staging API only, never production.

What fails the check

Missing field
The spec requires it; the response left it out.
Type changed
The spec says number; staging sent a string.
Undocumented status
A new error code the spec doesn’t list.

Caught on the pull request, not in a client team’s bug report

The same breaking change, two ways. Without a check, it travels to production and someone else finds it. With Contractcheck, it stops at the pull request that made it.

Today Found by a client team

  1. Pull requestSerializer changed; reviewers read the diff.
  2. MergedTests pass. Nothing compares the response to the spec.
  3. DeployedThe change reaches production.
  4. Client integratesTheir parser expects a number.
  5. Bug report“total is a string now?”Found here

With Contractcheck Found by the check

  1. Pull requestThe check runs the spec against staging and fails.Failed
  2. MergedOnly after it’s fixed.
  3. DeployedWith a matching response.
  4. Client integratesGets what the spec says.
  5. Bug reportNot filed.

The Postman collection that was meant to catch this only works when someone remembers to run it. Contractcheck runs on every pull request, so the spec gets checked whether anyone remembers or not.
