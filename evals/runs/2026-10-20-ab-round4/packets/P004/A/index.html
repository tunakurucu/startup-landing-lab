It fails in CI. Now it fails on your laptop too.

Rerun is a free command-line tool for backend engineers. It records a failing test run in CI and replays it on your machine: same inputs, same timing, same network responses.

Open source under the MIT license. Read the docs or browse the source on GitHub.

Install (npm)
$ npm install -g @rerun/cli

Free and MIT-licensed. No account needed.

The test is not random. Its inputs are.

A test that passes on your laptop and fails in CI is reading something different on each machine. Rerun records the four sources of that difference while the test runs in CI, then feeds the recorded values back in the same order on your laptop.

  • Clock Date · performance.now · timers

    Recorded
    Every read of the clock, and when each timer fired.
    Replayed
    The same values in the same order. A setTimeout(1200) that crossed midnight in CI crosses midnight again on your laptop at two in the afternoon.

  • Network http · https · fetch

    Recorded
    Each outgoing request with its response status, headers, body and latency.
    Replayed
    Responses are served from the recording. No pricing service, no staging database, no VPN. The test cannot tell the difference.

  • Randomness Math.random · crypto.randomUUID · randomBytes

    Recorded
    Every random value the process drew.
    Replayed
    The same draws, so generated ids, shuffled fixtures and sampled rows come out identical.

  • Environment process.env · argv · cwd · test order

    Recorded
    The variables, arguments and the order the runner chose for the files.
    Replayed
    Applied before the first test file loads, so TZ, feature flags and ordering match the CI run.

Two commands: one in CI, one on your laptop

The recorder wraps your existing test command. It costs nothing when the run passes; a failing run leaves a recording behind, and that recording is all the laptop needs.

  1. Wrap the test command in CI

    Prefix the command your pipeline already runs. On a green run the recording is discarded. On a red run it is written to .rerun/ and the run id is printed in the log.

  2. Keep the recording as a CI artifact

    One file per failing run. Upload it the way you upload coverage or screenshots, so anyone on the team can pull it later.

  3. Replay it on your laptop

    Rerun fetches the recording, starts the same test under it and stops at the same assertion. Attach your debugger, add a log line, replay again; the inputs do not move.

ci.yml · and your shellExample. Exact flags are in the docs.
# In CI: record the run. Nothing changes when tests pass.
$ npx rerun record -- npm test
  ✗ checkout › applies a coupon that expires at midnight
  rerun: wrote .rerun/ci-8841.rerun (1 failing test, 7 events, 41 KB)

# On your laptop: replay it.
$ rerun replay ci-8841
  rerun: pinned clock, 2 responses, 1 random draw, 14 env vars
  ✗ checkout › applies a coupon that expires at midnight
    expect(order.total).toBe(80)
    Expected: 80   Received: 100

Command names and output are illustrative; the docs have the current flags. The sample above is the same run the tape at the top replays.

What a replay cannot do yet

Rerun replays one Node.js process's inputs. Read this before you spend an afternoon on it.

  • Races between processes

    Two workers fighting over the same database row are a scheduling problem, not an input problem. Rerun replays what one process saw; it does not reproduce the operating system's interleaving.

  • Child processes and native addons

    Only the Node.js process that runs the tests is recorded. A subprocess, or a native addon that reads the clock or opens sockets outside Node's APIs, bypasses the recorder.

  • Node.js runners only

    The recorder hooks Node's clock, network and random APIs. Services written in Go, Java or Python are not supported today.

  • Recordings contain real data

    A recording holds response bodies and environment values from the CI run. Treat a .rerun file the way you treat a log file: keep it inside your CI artifact store and do not paste it into a public issue.
