Get slow work out of the request. Know where it went.

Drumbeat is an open-source job queue for Node. Your handler enqueues the email, export or webhook and answers right away; the job then runs, waits to retry or fails in states you can follow from start to finish.

Lifecycle reference

Five states, and what moves a job between them. Read this before you write a handler: the last column is what to check when a job stops where you didn’t expect.

queued → running → donerunning → waiting to retry → runningrunning → failed

StateA job enters whenIt leaves whenWhat to check
queued Your code enqueues it. The request can answer straight away. A worker picks it up. How long jobs sit here. A growing wait means work arrives faster than workers take it.
running A worker starts an attempt and calls your handler. The handler resolves, or throws. That the handler is safe to run twice. A retry repeats the whole attempt, so send-once side effects need a guard.
waiting to retry An attempt throws and attempts remain. Its backoff wait passes and it runs again. The last error and the next run time. Waits grow each time, so a stuck dependency gets room to recover.
done An attempt resolves. It doesn’t; done is final. Nothing, unless the handler resolved without doing its work.
failed The last allowed attempt throws. It doesn’t on its own; failed is final. Every attempt’s error, the cause, and whether to enqueue the work again once it is fixed.

These are the states this page models. Option names, defaults and exact state names belong to Drumbeat’s API reference; check them there before you depend on them.

What this page doesn’t claim

  • Throughput. No benchmarks have been published, so there are no jobs-per-second figures here. Measure with your own handlers and storage.
  • The timings. 4 ms, 2 s, 4 s and four attempts are example values for the model, chosen to make the rhythm visible.
  • The trace itself. It runs in your browser with no server, account or API key, and sends nothing anywhere. It shows the lifecycle, not the library executing.
