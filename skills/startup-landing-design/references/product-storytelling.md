# Make the promise inspectable

Assign one artifact to each main visitor doubt. Use an actual workflow rather than three abstract claims like fast, powerful and seamless.

Technical example: input event → retry policy → execution trace → final status. Show error and recovery, not only the happy path. If illustrative, use reserved .example domains and label sample data. Do not claim real measured latency.

Consumer example: starting material → playful choice → visible creation. The visitor should understand what they made and how to restart. Keep the activity optional and the main action obvious.

B2B example: unclear handoff → explicit owner and decision → review history. Trust comes from explaining control and limitations, not invented enterprise logos.

At each section ask what the visitor now knows that they did not know above. Delete sections that repeat the same claim. Put qualifications next to relevant promises, never in a separate section about what the company lacks or has not decided. Use real attributed proof only when supplied or verified. Otherwise use product behavior and honest scope.
