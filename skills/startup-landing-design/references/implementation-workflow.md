# Implementation workflow

1. Read the repository instructions and existing app entry points. Reuse its framework, route strategy and established components where useful. Do not replace its architecture to fit this skill.
2. Create a short design record: audience/doubts, reference jobs and non-borrowed treatments, hypothesis, section sequence, token roles and interaction contracts. Keep it proportional to the page.
3. Implement the real narrative before decorative effects. Use semantic headings and navigation; give every action a destination or observable result.
4. Build the signature artifact from original HTML/CSS/SVG or permitted assets. Prefer real text to screenshot text. Label sample interfaces. Use a static fallback if rich rendering fails.
5. Check assumptions: CTA makes the promised action possible; navigation works on narrow screens; controls aren't decorative; no fake quotes, financial claims, customers or signup success.
6. Build and run appropriate checks. Render actual pages at 1440×900, 768×1024 and 390×844 when available. Store screenshots with the project's normal artifact practice.
7. Critique the result before delivery, then make and verify one meaningful revision. Report the strongest remaining weakness.

For an existing brand, the signature idea may be a better workflow presentation within its current system. Originality does not authorize discarding its accessibility conventions or identity.
