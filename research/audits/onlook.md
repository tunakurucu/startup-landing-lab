## Observations

### Hero

Centered lightweight sans-serif statement; paired design/demo actions lead into a large editor canvas.

### Typography

Large lightweight sans-serif display and muted body text. The long FAQ uses a spacious split heading-and-question layout.

### Visual System

Near-black and dark gray surfaces, thin rules, broad editor imagery and restrained white actions.

### Page Sequence

Hero → canvas → code-aware design features → workflow capabilities → stack compatibility → community → FAQ → final action/footer.

### Interaction

Clicked the free-version FAQ question. aria-expanded changed to true. The hero showed “Error loading scene” in this browser; the intended scene was not evaluated.

### Accessibility

Semantic structure inspected through browser accessibility output. No contrast, keyboard, screen-reader or reduced-motion audit was completed.

## Interpretation

- Present the workspace as the product’s explanatory medium.
- Demonstrate continuity between visual editing and real code.
- Keep essential messaging and actions usable when a rich scene fails.

Choose this approach only if it explains the audience’s actual evaluation task.

Risk: The observed hero scene failure makes this an instructive resilience case, not an unqualified quality endorsement.

## Limitations

- Single browser, single inspection date; homepage content can change.
- Exact font names, animation timing and implementation libraries were not verified.
- Tablet, mobile and reduced-motion behavior remain unverified.
- Only selected regions were visually inspected; section sequence also uses rendered DOM. This is not a complete deep audit.
