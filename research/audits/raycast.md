- tablet: not inspected

## Observations

### Hero

Centered short headline and download action against black, followed by a launcher demonstration.

### Typography

Bold compact sans-serif headings, short body copy and monospace installation metadata.

### Visual System

Dark canvas, floating product surfaces, red and blue accents, framed extension panels and generous vertical gaps.

### Page Sequence

Hero → launcher preview → rationale → extension gallery → AI tools → professional proof → automation → notes → community → developer tools → final download/footer.

### Interaction

Full-page composition inspected. A workflow button seen during initial load could not be located after hydration, so its behavior is not verified. Download actions were not activated.

### Accessibility

Semantic structure inspected through browser accessibility output. No contrast, keyboard, screen-reader or reduced-motion audit was completed.

## Interpretation

- Use one interaction grammar across many capabilities.
- Alternate overview and close-up product views.
- Make platform requirements visible near the action.

Choose this approach only if it explains the audience’s actual evaluation task.

Risk: Initial-load and hydrated controls differed in this browser. Large blank intervals in a full-page capture may include unrevealed scroll content; do not infer animation implementation.

## Limitations

- Single browser, single inspection date; homepage content can change.
- Exact font names, animation timing and implementation libraries were not verified.
- Tablet, mobile and reduced-motion behavior remain unverified.
- Full-page composition and selected interaction states inspected on desktop; this does not imply responsive verification.
